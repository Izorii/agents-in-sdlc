GitHub Copilot をエージェントモードにすると、コードベースを調査し、変更を提案し、ファイルを編集して、コマンドを実行します。自分のマシン上でリアルタイムに作業するため、VS Code の Copilot Chat にはツールの呼び出しやファイル編集が逐次表示されます。エディターを離れずに、差分を確認して変更を個別に受け入れたり却下したりできます。また、追加のプロンプトで会話をガイドし、作業を改善または拡張できます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして受け入れます。
- セッション中にエージェントに指示し、高コントラストモードと並行してライトモードを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティカスタムエージェントは、高コントラストモードを実装しています。作業中に、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加してほしいというものです。新しい会話を最初から始めるのではなく、現在のセッションに指示を追加して作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが実行する各ステップが表示されます。調査したファイル、実行したコマンド、提案された編集などを確認できます。各ファイル編集は、差分と **Keep** / **Undo** コントロールとともにチャット内に表示されます。

1. 演習 4 で使用した Copilot Chat ビューに戻ります。
2. エージェントの作業中は、チャットをスクロールしてツールの呼び出しを確認します。ファイルの読み取り、編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイル編集を提案すると、差分がチャット内に表示されます。
   - 変更を受け入れるには **Keep** を選択します。
   - 変更を取り消してエージェントに再試行させるには **Undo** を選択します。
4. チャットの上部にある **Files changed** の表示を開くと、このセッションでエージェントが変更したファイル一式を確認できます。

> [!NOTE]
> ツールの呼び出しでターミナルコマンドの実行などに許可が必要な場合、エージェントは一時停止して **Allow** を求めます。許可するのは、実行してよいと判断したコマンドだけにしてください。

5. エージェントが高コントラストモードの実装を終えるまで待ちます。実行した変更をまとめた最終メッセージが表示されます。

## エージェントにライトモードの追加を依頼する

高コントラストモードができたら、同じ会話を続けてライトモードの切り替えを追加します。同じチャットセッションを使うことで、エージェントは以前の作業、変更したコンポーネント、スタイルの方法、ローカルストレージの利用方法などを引き続き把握できます。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントはすでに行った変更を調査し、ライトモードの追加を提案します。
3. 高コントラストモードのときと同様に、追加された編集をレビューし、差分ごとに **Keep** または **Undo** を選択します。
4. エージェントが意図しない方法で作業を進めた場合 (たとえば、好みと異なる方法で切り替え UI をリファクタリングする場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、明確にした追加メッセージを送ります。

> [!TIP]
> 作業中のセッションに指示を追加すると、最初からやり直すより早く修正できます。追加プロンプトで変更を依頼します (「CSS を簡潔にして、セレクターを重複させず CSS 変数を使う」)、方向を修正します (「3 つ目の切り替えを追加せず、既存の設定パネルにライトモードを追加する」)、または範囲を拡張します (「両方の切り替えにキーボードショートカットも追加する」)。

## 作業ファイル一式をレビューする

コミットする前に、エージェントが変更したファイルを確認します。

1. VS Code の **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティパターン (ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージへの保存など) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルで変更をステージしてコミットします。次の[レッスン][next-lesson]でブランチを公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使い、進行中のセッションを監視して指示を出しました。ファイル編集を確認して受け入れまたは却下し、コンテキストを失わずに追加プロンプトで作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を受け入れたり却下したりしました。
- 作業中に追加プロンプトを使ってセッションをガイドしました。

次の[レッスン][next-lesson]では、アクセシビリティの変更をプルリクエストとして公開し、このラボでカスタムエージェントが生成した変更をレビューします。
